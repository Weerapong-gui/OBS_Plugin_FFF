# แถบไลฟ์บนหน้า Monitor (เฟส 1 ของการทำ parity กับ dock)

- วันที่: 2026-09-19
- สถานะ: design อนุมัติแล้ว รอ implementation plan
- ต่อจาก: `0.4.0` (`/score` + OBS hotkeys)

## เป้าหมาย

หน้า `/monitor` ทำได้ทุกอย่างที่ dock **FFF Flag Board** ทำ ยกเว้นส่วนเซิร์ฟเวอร์และ
Monitor LAN งานทั้งหมดแบ่งเป็นสองเฟส เอกสารนี้คือ **เฟส 1: แถบไลฟ์**

เฟส 1 ครอบคลุมสิ่งที่ operator ต้องกดระหว่างออกอากาศ ซึ่งเป็นของที่คุ้มที่สุดต่อแรง
และเกือบทั้งหมดใช้ endpoint ที่มีอยู่แล้ว

## ข้อบังคับ (ห้ามละเมิด)

- **ห้ามเปลี่ยนพฤติกรรมการเชื่อมต่อ** — SSE, HTTP, heartbeat, retry, reconnect,
  `Connection: close` ทุกอย่างคงเดิมทั้งหมด งานปรับปรุงเครือข่ายถูกเลื่อนออกไปก่อน
- **ห้ามเปลี่ยน payload ของ SSE** — เฟรม overlay ถูกสร้างครั้งเดียวแล้วส่งให้ทุกเครื่อง
  รวมเครื่อง LAN การเพิ่มอะไรลงไปคือการแจกให้ทุกคน
- **dock ต้องทำงานเหมือนเดิมทุกประการ** — `dock-tests` ต้องผ่านโดยไม่แก้ไฟล์เทสต์
- **กติกาสิทธิ์เดิมต้องอยู่ครบ** — `/api/display` และ `/api/logo` ยังเป็น
  `Endpoint::LocalOnly` เครื่อง LAN ที่มีกุญแจถูกต้องก็ยังกดไม่ได้
- ห้าม refactor เรื่องที่ไม่เกี่ยวข้อง

## สิ่งที่ตัดสินใจไปแล้ว

1. **ปุ่มที่มีผลกับภาพออกอากาศ กดได้เฉพาะเครื่องที่รัน OBS** เครื่อง LAN เห็นปุ่มแต่
   `disabled` — รักษากติกา "on-air controls are local only" ที่อยู่ใน
   `fff-monitor-access.cpp` ไว้ทั้งหมด
2. **PIN ยังไม่ออกจากเครื่อง** (เรื่องของเฟส 2 แต่กำหนดทิศไว้แล้ว: ต้องมาทาง endpoint
   `LocalOnly` แยก ไม่ใช่ทาง SSE)
3. **แบ่งสองเฟส** เฟส 1 แถบไลฟ์ · เฟส 2 แท็บรายชื่อ + PNG อีก 4 ชนิด + Cover

## 2. API ที่เพิ่มและที่ขยาย

### 2.1 `POST /api/display` — ขยายให้สั่งซ่อนได้

วันนี้รับ `{"mode":"scoreboard"|"bottomBar"}` ผ่าน `validMode()` ซึ่ง **ไม่มีทางสั่ง
"ซ่อนจอ"** ส่วน dock เรียก `FffSession::hideDisplay()` ตรง ๆ ในโปรเซส

รับเพิ่มอีกรูปแบบหนึ่ง:

```jsonc
{"hide": true}      // → FffSession::hideDisplay()
```

- คำขอที่มี `mode` ทำงาน **เหมือนเดิมทุกประการ** ไม่มีพฤติกรรมใดเปลี่ยน
- คำขอที่มีทั้ง `mode` และ `hide` → `400` `{"error":"invalid request"}`
- คำขอที่มี `hide` แต่ไม่ใช่ `true` → `400`
- ยังเป็น `Endpoint::LocalOnly` เหมือนเดิม

เลือกขยาย endpoint เดิมแทนการเพิ่ม `/api/hide` เพราะการควบคุมภาพออกอากาศควรอยู่ที่
เดียว และไม่ต้องเพิ่มรายการใน `classify()` กับ `deniedText()`

### 2.2 `POST /api/round` — เริ่มรอบใหม่ (ใหม่)

```jsonc
{"action": "clear"}   // → FffSession::clearRound()
```

- `Endpoint::LocalOnly` — ต้องเพิ่มใน `classify()` และเพิ่มข้อความใน `deniedText()`
  (`"new round is local only"`)
- `action` ที่ไม่ใช่ `"clear"` → `400` — ไม่ยอมให้คำขอว่างเปล่าล้างรอบโดยบังเอิญ
- เซฟไม่สำเร็จ → `500` และ `clearRound()` คืนค่าเดิมให้เองอยู่แล้ว
- **ไม่มีกล่องยืนยันฝั่งเซิร์ฟเวอร์** การยืนยันเป็นเรื่องของ UI เหมือนที่ dock ทำ

### 2.3 `GET /api/monitor/capabilities` — ใหม่

```jsonc
{"onAir": true}    // เปิดจาก 127.0.0.1
{"onAir": false}   // เปิดจาก LAN ด้วยกุญแจ
```

- `Endpoint::MonitorApi` — หน้าเพจถูกรับเข้ามาแล้วจึงจะเรียกได้ กติกาเดียวกับหน้าเอง
- ค่าที่ตอบคือ `socket->peerAddress().isLoopback()` ตรง ๆ ไม่มีความลับใด ๆ อยู่ในนั้น
- หน้าเพจเรียกครั้งเดียวตอนโหลด ไม่ poll — ไม่เพิ่มภาระให้ช่องสัญญาณ

**ไม่แตะ `GET /api/monitor/access`** ซึ่งวันนี้ตอบ `204` และ `checkAccess()` ใน
`monitor-ui.js` พึ่งพาอยู่

### 2.4 ไม่ต้องแตะ SSE เลย

ทุกอย่างที่แถบไลฟ์ต้องแสดง อยู่ในเฟรมเดิมอยู่แล้ว:

| ต้องใช้ | มาจาก |
|---|---|
| โหมดที่ออกอากาศ, phase | `displayMode`, `phase` |
| รอบ, โหวตแล้ว X/Y | `round`, `voted`, `total` |
| Round ของโลโก้ + สำนักที่เลือก | `bottomBar.logoRound`, `bottomBar.logoPresidentId` |
| มี PNG Round 2 หรือยัง | `presidents[].logoRound2Url` (ว่าง = ยังไม่มี) |
| ใครโหวตสีอะไร | `presidents[].vote`, `.name`, `.school` |

## 3. เลย์เอาต์และการโต้ตอบ

แบ่งสองที่ ตามความถี่ในการใช้ และตามเหตุผลเดียวกับที่ dock ปักแถบไลฟ์ไว้เหนือแท็บ

```
┌ .monitor-top (ปักอยู่ ไม่เลื่อนหาย) ─────────────────────────┐
│ จอมอนิเตอร์  [● ออกอากาศ · BOTTOM BAR]  รอบ 2 · 8/14  บันทึก…│
│ แก้ไขโหมด (Show Status|BOTTOM BAR)  ชิ้นงาน [▾]  ธง  สถานะ   │
│ ─── แถวใหม่ ─────────────────────────────────────────────── │
│ ออกอากาศ: [Show Status] [BOTTOM BAR] [■ ซ่อนจอ] [↻ รอบใหม่] │
└──────────────────────────────────────────────────────────────┘
   แท็บ: ตำแหน่ง · ตาราง · แม่แบบ · PNG สถานะ · จังหวะ · หน้า Score · ไลฟ์ ←ใหม่
         ├ โลโก้กลาง  [Round 1] [Round 2]   สำนัก [▾]
         │  ⚠ สำนักสอง ยังไม่มี PNG ของ Round 2
         └ ใครโหวตแล้ว
             ● เขียว · หนึ่ง
             ○ ยังไม่กด · สอง
```

### กติกา

- **ปุ่มโหมดเป็น toggle เหมือน dock เป๊ะ** — กดโหมดที่ออกอากาศอยู่ซ้ำ = ลงจอ
  (`{"hide":true}`) กดอีกโหมด = สลับตรง ๆ ตรรกะเดียวกับ `FffLivePanel::toggleMode()`
- **↻ เริ่มรอบใหม่ ใช้ `armConfirm()` ที่มีอยู่แล้ว** ใน `monitor-ui.js` (กดสองครั้ง
  ภายใน `fffTiming.monitor.confirm`) — ตัวเดียวกับที่ `#resetAll` ใช้ ไม่เขียนกล่อง
  ยืนยันใหม่ และไม่ใช้ modal เพราะหน้านี้อาจอยู่บนมือถือ
- **เปิดจาก LAN → ปุ่มทั้งสี่ + Round 1/2 + สำนัก เป็น `disabled` พร้อม `title`**
  ว่า "ใช้ได้เฉพาะเครื่องที่รัน OBS" — ปิดการใช้งาน ไม่ซ่อน เพื่อให้เลย์เอาต์ไม่ขยับ
  กติกาเดียวกับปุ่มธงตอนยังไม่ได้เลือกการ์ด
- **รายการคนโหวตและคำเตือน Round 2 แสดงทุกเครื่อง** อ่านอย่างเดียว ไม่มีปุ่ม
- ปุ่มที่ออกอากาศอยู่ได้สถานะ `aria-pressed="true"` และพื้นสีฟ้า เหมือนปุ่มโหมดใน dock
- แถบเตือนสีเหลือง "กำลังแก้โหมดที่ออกอากาศอยู่" ที่มีอยู่แล้วทำงานเหมือนเดิม
- แท็บ **ไลฟ์** เข้าระบบจำแท็บล่าสุดของ `createTabs()` อัตโนมัติ ไม่ต้องแก้อะไร

### ข้อจำกัดของเลย์เอาต์

`monitor-ui.cjs` มีเกณฑ์ว่า **หน้าต่างกว้าง 900px ต้องไม่มี horizontal scroll** แถวปุ่ม
ใหม่ต้อง `flex-wrap` และปุ่มต้องยุบขนาดได้ ไม่งั้นเทสต์เดิมจะพัง — ถือเป็นเกณฑ์ตัดสิน
ว่าเลย์เอาต์นี้ใช้ได้จริงหรือไม่

## 4. การไหลของข้อมูลและการจัดการข้อผิดพลาด

```
โหลดหน้า → GET /api/monitor/capabilities → เก็บ onAir ไว้ในตัวแปรเดียว
                                          → paint ปุ่มเป็น enabled/disabled
SSE (เดิม) → render() → อัปเดตสถานะปุ่ม, Round, สำนัก, คำเตือน, รายการโหวต
กดปุ่ม → POST (display/logo/round) → 200 → รอ SSE เฟรมถัดไปเป็นตัวยืนยัน
                                   → 403 → "ใช้ได้เฉพาะเครื่องที่รัน OBS"
                                   → 500 → ข้อความบันทึกไม่สำเร็จเดิม
                                   → ขาดการเชื่อมต่อ → แถบเตือนเดิม
```

- **หน้าเพจไม่เดาผลลัพธ์เอง** — กดแล้วรอ SSE ยืนยัน เหมือนที่ปุ่มธงกับปุ่มสถานะทำอยู่
  ป้องกันไม่ให้ปุ่มกับภาพที่ออกอากาศจริงไม่ตรงกัน
- ระหว่างรอคำตอบ ปุ่มที่กด `disabled` ชั่วคราว กันกดซ้ำ
- ใช้ `SAVE_TIMEOUT_MS` กับ `AbortController` แบบเดียวกับแผงจังหวะและแผงหน้า Score

### manual (ใน OBS จริง)

1. เปิด `/monitor` บนเครื่อง OBS กดทั้งสี่ปุ่ม → Browser Source เปลี่ยนตรงกับกดที่ dock
2. เปิด dock และ `/monitor` พร้อมกัน กดสลับไปมา → สถานะปุ่มทั้งสองที่ตรงกันเสมอ
3. เปิด `/monitor?key=…` จากเครื่องอื่นใน LAN → ปุ่มทั้งสี่เทา มี tooltip บอกเหตุผล
   แต่กระดาน แม่แบบ และการลากยังทำงานครบ
4. กด ↻ เริ่มรอบใหม่ จาก monitor → โหวตถูกล้าง มือถือทุกเครื่องกลับไปยังไม่เลือกสี
5. ปิด-เปิด OBS → แท็บล่าสุดยังถูกจำ

## 6. สิ่งที่ยังเปิดอยู่

- **เฟส 2 ยังไม่ได้ออกแบบ** — แท็บรายชื่อจะพา PIN ออกนอกโปรเซสเป็นครั้งแรก ต้องมี
  เอกสารของตัวเองและต้องตัดสินใจเรื่อง `GET /api/roster` ที่เป็น `LocalOnly`
- **งานปรับปรุงเครือข่ายถูกเลื่อน** ตามที่ตกลงไว้ ถ้าเฟส 1 ทำให้เห็นว่าการกดปุ่มจาก
  หน้าเว็บช้ากว่ากดที่ dock อย่างมีนัย ให้กลับไปที่เอกสารนั้นก่อน ไม่ใช่แก้ตรงนี้
